# Как контрибьютить

## Ветки и PR

```
main                 защищённая ветка, только через PR
feat/<название>      новая функциональность
fix/<название>       исправление
docs/<название>      документация
```

1. `git checkout -b feat/my-feature`
2. Правки + тесты
3. `python -m pytest` — зелёный
4. PR в `main` с описанием: что меняется, зачем, как проверено
5. Ревью: минимум один человек/агент, знакомый с `AGENTS.md`

Один PR — одна задача. Не смешивайте переименование файлов и логику.

## Требования к коду

- Python 3.11+, type hints в `app/`, docstring у модуля.
- Никаких новых зависимостей без обсуждения (см. `requirements.txt`).
- Логика — в `app/services/`, HTTP — в `app/api/`. В роутерах не должно быть бизнес-правил.
- Ошибки бизнес-логики — через `TaskError` (→ 409) или `KeyError` (→ 404).
- Тексты для пользователя — по-русски.

## Тесты

- Новая логика детектора/сроков — тест в `tests/test_detect.py` или `tests/test_deadline.py`.
- Новый эндпоинт — тест в `tests/test_api.py`.
- Изменение поведения на реальных данных — прогон `tests/test_corpus.py`.

## Данные и секреты

Не коммитить: `.env`, `*.db`, `*.exe`, `*.m4a`, реальные телефоны и имена.
Демо-данные — только синтетические, телефоны маскируются (`scripts`/`data/README.md`).

## Коммиты

```
feat: добавить фильтр по оператору
fix: не считать вопрос обещанием
docs: описать формат вебхука
test: покрыть парсер сроков для «через полтора часа»
```

Сообщение — в императиве, по-русски, до 72 символов в первой строке.
