# Деплой сервиса контроля обещаний

Практическая инструкция: как поднять этот FastAPI-сервис на бесплатном хостинге и что при этом
теряется. Без обещаний «бесплатно и надёжно»: бесплатные тарифы дают работающий URL, но не дают
гарантий и не сохраняют данные.

## Что деплоим и почему это важно

- Приложение: `app.main:app` (FastAPI + uvicorn), статика панели раздаётся самим приложением.
- Хранилище: **один файл SQLite**, путь из `DATABASE_PATH` (по умолчанию `data/promises.db`,
  в контейнере — `/app/data/promises.db`).
- Порт: контейнер слушает `$PORT` (если переменная не задана — 8080). Render подставляет свой порт,
  Hugging Face Spaces ждёт приложение на 7860.
- Часовой пояс сроков: `APP_TIMEZONE` (по умолчанию `Asia/Yekaterinburg`).

Сервис **stateful**: звонки, задачи и история лежат в SQLite-файле. Поэтому главный вопрос любого
бесплатного хостинга — не «запустится ли», а «что будет с файлом базы при рестарте».
На всех трёх вариантах ниже файловая система эфемерна: после рестарта база пустая,
но схема и справочник типов создаются заново автоматически (`init_db()` в `app/main.py`).

| Файл | Зачем |
|---|---|
| `Dockerfile` | python:3.12-slim, зависимости из `requirements.txt`, пользователь UID 1000, `EXPOSE 8080`, запуск через `sh -c` с `${PORT:-8080}` |
| `.dockerignore` | не тащим в образ `.git`, `.venv`, `__pycache__`, локальную БД, `local/`, `*.exe`, `*.m4a`, `*.docx`, `*.pdf` |
| `render.yaml` | Blueprint Render: web, runtime docker, plan free, healthCheckPath `/health`, переменные окружения |
| `docs/DEPLOY.md` | этот файл |

Локальная проверка образа (без хостинга):

```bash
docker build -t promise-service .
docker run --rm -p 8080:8080 promise-service
curl http://localhost:8080/health
```

## Вариант A. Render (основной)

### Шаги

1. Репозиторий должен быть на GitHub (Render деплоит из Git, не из локальной папки).
2. В Render: **New → Blueprint**, выбрать репозиторий. Render прочитает `render.yaml` и создаст
   сервис `promise-service` с планом free.
   Если Blueprint не нужен — **New → Web Service**, Language: **Docker**, Branch: `main`,
   Dockerfile Path: `./Dockerfile`, Health Check Path: `/health`, Instance Type: **Free**.
3. Переменные окружения (уже прописаны в `render.yaml`):
   `DATABASE_PATH=/app/data/promises.db`, `APP_TIMEZONE=Asia/Yekaterinburg`.
4. Дождаться первого деплоя, открыть `https://<имя-сервиса>.onrender.com/health`.

### Ограничения free-тарифа (по документации Render)

- **Засыпает через 15 минут** без входящего трафика (HTTP-запросы и WebSocket-сообщения).
  Health check хостинга сервис не будит.
- **Холодный старт около минуты** — Render показывает заглушку, пока контейнер поднимается.
  На практике 30–60 с, иногда дольше; первый `curl` может «висеть».
- **Файловая система эфемерна**: изменения теряются при каждом редеплое, рестарте и засыпании.
  То есть `promises.db` живёт до первого сна — вместе с задачами и звонками.
- **Persistent disk на free недоступен**: диски подключаются только к платным планам.
  Поэтому блок `disk:` в `render.yaml` закомментирован — с ним Blueprint на free не создастся.
- 750 инстанс-часов в месяц на рабочее пространство; при исчерпании сервисы приостанавливаются
  до начала следующего месяца.
- Нет SSH/шелла, нет масштабирования больше одного инстанса, Render может перезапустить сервис
  в любой момент.
- Исчерпание бесплатного трафика/минут сборки ведёт к приостановке сервисов.

Источники: [Free instances](https://render.com/docs/free), [Persistent disks](https://render.com/docs/disks).

### Как получить сохранные данные

1. Платный план (например `starter`) + раскомментировать блок `disk:` в `render.yaml`
   (mountPath `/app/data`, sizeGB 1). Учтите: с диском деплой идёт с простоем
   (Render останавливает старый инстанс перед новым).
2. Либо перейти на PostgreSQL — это правка кода (`app/db.py`, SQL-диалект), в текущих артефактах
   не сделана и здесь не обещается.

### Обновление

`autoDeployTrigger: commit` — пуш в `main` запускает передеплой. Данные при этом стираются
(см. выше).

## Вариант B. Hugging Face Spaces (Docker SDK)

Даёт публичный URL на бесплатном CPU-инстансе, без карты. Полезно, если GitHub/Render недоступны.

### Шаги

1. **New Space** → SDK: **Docker** → шаблон Blank → видимость Public → hardware CPU basic (free).
2. Загрузить содержимое репозитория в Space (git remote на `https://huggingface.co/spaces/<user>/<space>`).
3. В `README.md` Space нужен YAML-заголовок с `sdk: docker`; в этом репозитории его нет,
   поэтому добавьте метаданные в Space (Settings) или отдельный README Space-репозитория.
4. **Порт 7860**: Space проксирует трафик на 7860. Наш `CMD` читает `PORT`, поэтому в
   Settings → Variables добавьте `PORT=7860` (иначе uvicorn поднимется на 8080 и Space отдаст ошибку).
5. Переменные: `DATABASE_PATH=/app/data/promises.db`, `APP_TIMEZONE=Asia/Yekaterinburg`.
6. Контейнер в Spaces запускается от **UID 1000** — `Dockerfile` уже создаёт пользователя с этим UID,
   права на `/app/data` сохраняются.

### Ограничения

- **Диск эфемерный**: записанное теряется при рестарте/пересборке Space. Раздел `/data` доступен
  только в рантайме; постоянное хранение — через Storage Bucket, это отдельный сценарий и в наших
  файлах не настроен.
- **Пространство публичное**: панель и API открыты любому, у кого есть ссылка, включая
  `POST /webhook/calls`. Единственная защита в коде — `WEBHOOK_TOKEN` (заголовок `X-Webhook-Token`),
  и она закрывает только вебхук; `/api/v1/*` и панель остаются без авторизации.
- Бесплатные Spaces также останавливаются при простое; конкретные сроки в этой проверке не
  уточнялись — смотрите актуальную документацию HF, поведение может меняться.
- CPU basic — минимальный бесплатный инстанс: для демо с 52 звонками достаточно,
  для нагрузки контакт-центра нет.

Источник: [Docker Spaces](https://huggingface.co/docs/hub/spaces-sdks-docker).

## Вариант C. PythonAnywhere — почему неудобно

Формально FastAPI там запускается, но это самый дорогой по времени путь из трёх.

- **ASGI — экспериментальная функция.** Обычные веб-приложения на PythonAnywhere — WSGI.
  Для ASGI есть beta-режим: сайт создаётся не через Web UI, а командой вида
  `pa website create --domain <user>.pythonanywhere.com --command '<venv>/bin/uvicorn --app-dir /home/<user>/promise-service --uds ${DOMAIN_SOCKET} app.main:app'`.
  В документации прямо сказано: интерфейс командной строки и API могут измениться,
  долгосрочные тарифы для ASGI ещё не определены, UI для управления такими сайтами почти нет.
- **Dockerfile не используется.** Наши `Dockerfile` и `render.yaml` там бесполезны: зависимости
  ставятся в virtualenv вручную, переменные окружения задаются через `.env` или настройки веб-приложения.
  То есть деплой невоспроизводим — расходится с локальным запуском.
- **SQLite неудобен.** Файл лежит в домашнем каталоге: один писатель на базу, поэтому при
  нескольких процессах/воркерах появляются блокировки (`database is locked`), а ёмкость ограничена
  квотой диска аккаунта. Отдельного «диска» с бэкапами, как у Render, нет; при очистке файлов
  или пересоздании аккаунта база исчезает. Для read-only демо это терпимо, для приёма звонков — нет.
- Статические файлы раздаёт само приложение (FastAPI `StaticFiles`), так что отсутствие
  static-маппингов в ASGI-режиме здесь не критично — но это единственный плюс.

Источник: [Deploying ASGI sites on PythonAnywhere (beta)](https://help.pythonanywhere.com/pages/ASGICommandLine).

**Вывод:** PythonAnywhere годится, чтобы показать `/docs` и панель, но не для демонстрации
приёма звонков; настройка займёт больше времени, чем Render.

## Общие ограничения любого бесплатного варианта

1. **Данные не сохраняются.** SQLite-файл стирается при рестарте/сне/редеплое на всех трёх
   вариантах. Единственное исключение — платный диск Render или внешняя БД.
2. **Сервис засыпает.** Первый запрос после простоя — медленный (у Render около минуты).
   Сценарий «отправитель шлёт звонки по расписанию, а сервис спит» приведёт к таймаутам у отправителя.
3. **Нет SLA.** Инстанс могут перезапустить или приостановить в любой момент.
4. **Публичный API без авторизации.** CORS в `app/main.py` открыт (`allow_origins=["*"]`),
   `/api/v1/*` и панель не защищены, `WEBHOOK_TOKEN` по умолчанию не задан.
   Для хакатонного демо — приемлемо; для реальных данных — нет.
5. **Одна реплика, один процесс.** SQLite и in-process состояние не масштабируются.

## Чек-лист проверки после деплоя

Замените `HOST` на выданный адрес, например `promise-service.onrender.com`.

1. **Живость**

   ```bash
   curl -i https://HOST/health
   ```

   Ожидается `200` и JSON: `"status":"ok"`, `"database":"sqlite"`,
   `"timezone":"Asia/Yekaterinburg"`, `"types":` ≥ 7, `"tasks": 0` на свежей базе.
   Если 502/таймаут — сервис ещё поднимается после сна, повторите через минуту.

2. **Swagger**

   Открыть `https://HOST/docs` — должны быть видны `POST /webhook/calls`, `GET /api/v1/tasks`,
   `PATCH /api/v1/tasks/{id}`, `GET /api/v1/stats`, `GET /health`.

3. **Тестовый звонок с обещанием**

   ```bash
   curl -X POST https://HOST/webhook/calls \
     -H "Content-Type: application/json" \
     -d '[{"id":"deploy-test-1","operator_id":3,"client_phone":"+79800908260",
           "started_at":"2026-10-30T09:00:00Z","ended_at":"2026-10-30T09:05:00Z",
           "transcript":[
             {"speaker":"client","text":"Когда будет счёт?"},
             {"speaker":"operator","text":"Перезвоню завтра до обеда и отправлю счёт."}
           ]}]'
   ```

   Ожидается `200`, `"processed": 1`, `"tasks_created"` ≥ 1 (у оператора два обещания — перезвон
   и счёт, поэтому задач может быть две). Повторная отправка того же `id` вернёт
   `"duplicates": 1` и новых задач не создаст — это проверка идемпотентности.
   Если задан `WEBHOOK_TOKEN`, добавьте заголовок `-H "X-Webhook-Token: <значение>"`,
   иначе будет `401`.

4. **Задачи**

   ```bash
   curl "https://HOST/api/v1/tasks?limit=5"
   ```

   Ожидается `items` с полями `id`, `title`, `promise_type`, `due_at`, `status` (`created`),
   `is_overdue`. Срок считается от `ended_at` в поясе `APP_TIMEZONE`.

5. **Сводка и панель** (необязательно, но быстро)

   ```bash
   curl https://HOST/api/v1/stats
   ```

   И открыть `https://HOST/` — задачи из п.4 должны быть в списке.

6. **Проверка эфемерности (осознанный шаг)** — перезапустить сервис
   (Render: Manual Deploy → Restart, либо дождаться сна на 15 минут) и повторить п.4:
   на бесплатном тарифе задачи исчезнут. Это ожидаемое поведение тарифа, а не дефект сервиса;
   фиксируйте его в отчёте честно.

## Что осталось за рамками
