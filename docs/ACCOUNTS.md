# Аккаунты, вход и подписка

Добавлено поверх сервиса контроля обещаний: личный кабинет, вход по почте или
через Telegram-бота, тариф FREE/PRO и реклама в панели для бесплатного тарифа.

## Как устроен вход

| Способ | Что происходит |
|---|---|
| Почта | `POST /api/v1/auth/email/request` создаёт одноразовую ссылку на 10 минут. Если настроен SMTP — письмо уходит на адрес; если нет — dev-режим: ссылка возвращается в ответе и показывается на `/account`. |
| Telegram | Бот по `/start` присылает шестизначный код на 10 минут. Сайт меняет его на сессию через `POST /api/v1/auth/telegram/claim`. |

Сессия — случайный токен в HttpOnly-cookie `promise_session` на 30 дней; в базе
хранится сам токен, поэтому выход удаляет запись и cookie сразу.

Таблицы `users`, `sessions`, `login_codes` создаются автоматически при первом
обращении к любому методу входа (`app/services/users.py`), основная схема не тронута.

## Запуск Telegram-бота

```powershell
$env:TELEGRAM_BOT_TOKEN = "123456:ABC..."
python -m app.bot
```

Бот работает через `getUpdates` (long polling), вебхук не нужен. Команды: `/start`
и `/code`. Если токена нет — процесс завершается с подсказкой, сервис при этом
работает, просто вход остаётся по почте.

## Подписка и реклама

- `FREE` — в панели показывается полоса «оформить PRO», в кабинете — рекламный слот.
- `PRO` — реклама скрывается (`ads: false` в `/api/v1/auth/me`).

```
POST /api/v1/billing/subscribe   # план PRO
POST /api/v1/billing/cancel      # обратно FREE
```

**Честно: платёжного провайдера нет.** Подписка включает тариф локально и
возвращает `mock_payment: true`. Для реальных денег нужен эквайринг (ЮKassa,
Stripe) и вебхук подтверждения оплаты — это отдельная задача.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/auth/email/request` | запросить ссылку на почту |
| GET | `/api/v1/auth/email/confirm?token=…` | подтвердить вход, выдать cookie |
| POST | `/api/v1/auth/telegram/claim` | войти по коду из бота |
| GET | `/api/v1/auth/me` | кто вошёл, тариф, нужна ли реклама |
| POST | `/api/v1/auth/logout` | выйти |
| GET | `/api/v1/me` | профиль (алиас, без префикса auth) |
| PATCH | `/api/v1/me` | привязать `operator_id` |
| GET | `/api/v1/me/tasks` | «мои обещания» — задачи этого оператора |
| POST | `/api/v1/billing/subscribe` | включить PRO (демо) |
| POST | `/api/v1/billing/cancel` | отменить PRO |
| GET | `/account` | страница кабинета |

## Ограничения

- Нет ограничения частоты запросов на `email/request` — в проде нужен rate limit,
  иначе адрес можно засыпать письмами.
- Dev-режим показывает ссылку в ответе API: это удобно локально, но недопустимо
  на публичном хосте. На деплое задайте SMTP или закройте регистрацию.
- Нет подтверждения почты отдельным шагом: вход по ссылке уже доказывает доступ.
- Нет ролей: любой вошедший видит задачи только своего `operator_id`, админки нет.
- Подписка не связана с оплатой (см. выше).
