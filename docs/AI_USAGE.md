# Ответственное использование ИИ

Кейс требует честно перечислить инструменты и объяснить, что именно сделано с их помощью.

## Что использовалось

| Инструмент | Как применялся | Что проверено человеком |
|---|---|---|
| **AutoClaw** (LLM-агент) | Генерация кода сервиса, тестов, документации; разбор кейса и аудиозаписи | Архитектура и логика детектора, парсера сроков и статусов; прогон тестов; ручная проверка выборки задач |
| **faster-whisper** (локально, CPU, модель `medium`) | Расшифровка аудиозаписи брифинга организаторов (12 минут) | Ключевые тезисы сверены с текстом кейса и памяткой жюри |
| **GitHub API** | Создание публичного репозитория и загрузка кода | — |

Модель не использовалась как источник фактов: все числа в README и документации получены прогоном
кода на данных кейса (`python -m pytest`, `scripts/seed_demo.py`).

## Что ИИ не делал

- не придумывал требования: они взяты из `.docx`, `.pdf` и записи брифинга;
- не оценивал качество решения вместо нас: выводы о точности сделаны по прогону и ручной выборке;
- не получал доступа к чужим данным: телефоны в датасете замаскированы, токены в репозитории отсутствуют.

## Данные

- Все звонки **синтетические**, предоставлены организаторами кейса.
- Телефоны в `data/sample_calls.json` замаскированы (`+7*******50`).
- `.env`, `*.db`, токены и аудиозапись — в `.gitignore` и не публикуются.

## Ограничения, о которых нужно сказать на защите

1. Поиск обещаний — правила и лексика, а не большая языковая модель. Незнакомые формулировки
   могут не распознаваться; на подготовленных данных кейса результат устойчивый.
2. LLM-адаптер есть в коде (`app/services/llm.py`), но по умолчанию выключен и на реальном ключе
   в этом окружении не проверялся — поэтому в оценку качества не заявляется.
3. Проверка исполнения по следующим звонкам понимает только явные формулировки («перезвонили»,
   «счёт не пришёл»); ирония и намёки остаются без реакции.
4. Праздничные дни при расчёте рабочих дней не учитываются.
5. SQLite и один процесс: для реальной нагрузки нужен PostgreSQL.

## Как проверялся результат

| Проверка | Команда | Результат |
|---|---|---|
| Модульные и сквозные тесты | `python -m pytest` | 88 тестов, все зелёные |
| LLM-режим | `tests/test_llm.py` | включается флагом, при сбое сети приём звонков не ломается |
| Парсер сроков | `tests/test_deadline.py` | 25 формулировок, включая «завтра до обеда» и «в течение трёх рабочих дней» |
| Детектор | `tests/test_detect.py` | реплики клиента, вопросы, прошедшее время не считаются обещаниями |
| Реальные данные | `tests/test_corpus.py`, `scripts/seed_demo.py` | 52 звонка → 189 задач, 3,63 на звонок |
| Новые данные из API | `tests/test_extra_corpus.py` | 48 незнакомых звонков → 170 задач, ошибок нет |
| Проверка исполнения | `tests/test_verify.py` | подтверждение закрывает задачу, опровержение помечает «не выполнено», вопросы и чужой номер игнорируются |
| Идемпотентность | повторный `POST /webhook/calls` | 52 дубля, 0 новых задач |
