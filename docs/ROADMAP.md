# План работ

Бэклог для продолжения после хакатона. Метки: **P1** — нужно для пилота, **P2** — развитие,
**P3** — когда появится время. Один пункт = один PR.

## P1 — довести до пилота

- [x] **Проверка исполнения обещания.** Задача связывается со следующими звонками клиента по
      `client_phone`, подтверждение закрывает её, опровержение помечает «не выполнено»
      (`services/verify.py`, `tests/test_verification.py`).
  - осталось: расширять словарь формулировок по реальным разговорам и считать точность.
- [ ] **Аутентификация.** `X-Service-Token` для вебхука (уже есть `WEBHOOK_TOKEN`), токен оператора
      для `PATCH /tasks`, ограничение CORS списком origin.
- [ ] **Миграции БД.** Сейчас схема создаётся `CREATE TABLE IF NOT EXISTS`; нужен версионный
      механизм (`PRAGMA user_version` уже пишется, но не читается).
- [ ] **Ручная выборка качества.** Разметить 30 задач (тип + срок) и посчитать precision/recall
      детектора. Результат — в `docs/QUALITY.md`.
- [ ] **Логи и метрики.** Структурные логи приёма звонка, счётчики: принято, создано задач,
      ошибок детектора, среднее время обработки.

## P2 — расширение

- [ ] **PostgreSQL + очередь.** Вынести репозиторий в слой `storage/`, добавить Alembic.
- [ ] **Эмбеддинги для своих типов.** Заменить лексическое пересечение в `_custom_candidates`
      на косинусную близость (описание и примеры уже хранятся).
- [ ] **Праздничный календарь РФ** для расчёта рабочих дней.
- [ ] **Мультитенантность.** `team_id` в звонках и задачах, изоляция данных команд.
- [ ] **Напоминания оператору.** За 30 минут до срока — уведомление (Telegram/MAX),
      в API партнёра есть `notify_channel`.
- [ ] **Массовые операции.** `PATCH /api/v1/tasks` со списком id.

## P3 — удобство

- [ ] **Экспорт в CSV/XLSX** для руководителя смены.
- [ ] **Графики** в панели: динамика обещаний по дням, доля выполненных, топ операторов.
- [ ] **Тёмная тема** и клавиатурные сокращения в панели.
- [ ] **Docker Compose** для запуска одной командой на Linux.
- [ ] **i18n** интерфейса (русский/английский).

## Технический долг

- [ ] `app/api/calls.py` содержит служебный `_call_to_out` — вынести в `services/serializers.py`.
- [ ] `detect.py` разросся: разделить лексику (`taxonomy.py`) и правила (`rules.py`).
- [ ] **CI.** GitHub Actions: `pytest` на каждый push, затем `ruff` и `mypy`.
- [ ] Покрытие тестами `deadline.py` — 25 кейсов, добавить «через полтора часа», «в конце месяца».
- [ ] Проверить поведение при 10 000 задач: индексы есть, но нужен замер.

## Что не делать

- Не тащить в основной путь внешние сервисы: сервис должен запускаться офлайн одной командой.
- Не заменять правила LLM целиком: объяснимость важнее «умности» на защите.
- Не хранить персональные данные в открытом виде: телефоны маскируются при импорте.
