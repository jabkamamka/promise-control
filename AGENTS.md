# AGENTS.md — правила работы в этом репозитории

Файл для людей и для ИИ-агентов, которые подключаются к проекту.
Если ты вторая модель/разработчик — прочитай этот файл целиком перед первой правкой.

## Что это за проект

Сервис контроля обещаний (кейс УралМикро, хакатон 2026). Принимает расшифровки звонков,
находит обещания оператора, создаёт задачи со сроком, ведёт статусы.

**Стек:** Python 3.11+, FastAPI, Pydantic v2, SQLite (stdlib `sqlite3`), pytest.
Фронтенд — один HTML-файл + ванильный JS, без сборки. Никаких других зависимостей без согласования.

## Как запустить

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m pytest                      # 65 тестов должны быть зелёными
python -m uvicorn app.main:app --port 8080
python scripts\seed_demo.py           # 52 демо-звонка, если нужна база с данными
```

## Карта кода

| Файл | Ответственность | Что нельзя ломать |
|---|---|---|
| `app/services/taxonomy.py` | Типы обещаний, глаголы, объекты, адресаты | Коды встроенных типов (`callback`, `documents`, `clarification`, …) |
| `app/services/detect.py` | Поиск обещаний в репликах | Контракт `DetectedPromise` |
| `app/services/deadline.py` | Русский срок → дата/время | Порядок приоритетов разбора |
| `app/services/ingest.py` | Приём звонков, идемпотентность | `dedupe_key`, формат ответа вебхука |
| `app/services/tasks.py` | Выборка, статусы, просрочка, статистика | `TRANSITIONS`, вычисление `effective_status` |
| `app/api/*.py` | HTTP-слой | Пути и поля ответов из `docs/API.md` |
| `app/db.py` | Схема SQLite | Имена таблиц и колонок |

## Жёсткие правила

1. **Контракт API менять только вместе с `docs/API.md`** и предупреждением в PR.
   Ломающее изменение — отдельный PR с пометкой `breaking`.
2. **Каждая правка логики — с тестом.** Минимум: `python -m pytest` зелёный.
   Новое правило детектора без теста не принимается.
3. **Не коммитить секреты и данные:** `.env`, `*.db`, `*.exe`, `*.m4a`, реальные персональные данные.
4. **Не менять чужие файлы «попутно».** Один PR — одна задача. Форматирование всего файла
   вместе с логической правкой затрудняет ревью.
5. **Ветки:** `feat/<короткое-название>`, `fix/<...>`, `docs/<...>`. В `main` — только через PR.
6. **Стиль:** type hints обязательны в `app/`, docstring у каждого модуля, сообщения и интерфейс — по-русски.
7. **Никаких новых внешних сервисов** (БД, очереди, LLM) в основном пути: сервис должен запускаться
   одной командой на школьном компьютере без интернета.
8. **Честность в документации:** если что-то не реализовано или не проверено — так и писать.

## Что уже решено (не переделывать без причины)

- **Правила вместо LLM по умолчанию.** Нужна объяснимость и работа офлайн. LLM — опциональный адаптер.
- **Одна задача на одну реплику-обещание.** Несколько вопросов в звонке → несколько реплик → несколько задач.
- **Просрочка вычисляется, а не хранится в `status`.** В БД только `created/in_progress/done`.
- **Идемпотентность через `dedupe_key`** = hash(call_id + тип + индекс реплики + текст).
- **Срок по умолчанию 24 часа**, если в реплике нет даты.
