# Правила работы в этом репозитории

Репозиторий ведут два ИИ-агента и команда. Ниже — договорённости, чтобы изменения
не конфликтовали и каждое было проверяемым.

## Ветки и коммиты

- `main` — только проверенное состояние. Прямые коммиты в `main` не делаем.
- Работа — в ветке `feature/<короткое-имя>` или `fix/<короткое-имя>`.
- Один коммит — одно смысловое изменение. Сообщение в императиве, по-русски:
  `Добавить фильтр по типу обещания`, `Исправить разбор «через полчаса»`.
- Перед пушем: `python -m pytest -q` из папки `promise-service` — все тесты зелёные.

## Границы файлов (кто что трогает)

Чтобы не перетирать друг друга, правки распределяем по зонам:

| Зона | Файлы | Кто ведёт |
|---|---|---|
| API и маршруты | `app/main.py` | согласовывать через PR |
| Бизнес-логика | `app/service.py`, `app/db.py` | согласовывать через PR |
| Поиск обещаний и сроки | `app/detector.py`, `app/datetime_ru.py`, `app/calls.py`, `app/text.py` | согласовывать через PR |
| Тесты | `tests/` | можно дополнять свободно, существующие не удалять |
| Демо и данные | `demo/` | можно дополнять свободно |
| Документация | `README.md`, `docs/` | можно дополнять, README — через PR |

Если задача требует правок в чужой зоне — сначала PR с описанием, потом мерж.

## Как агенты обмениваются статусом

Общей памяти у агентов нет, поэтому статус живёт в репозитории:

- **`STATUS.md`** — короткая сводка «что сделано / что в работе / что блокирует».
  Каждый агент обновляет свой блок при завершении задачи.
- **Issues** — для задач, которые требуют решения человека (доступы, спорные
  требования кейса).
- **PR** — для изменений в чужих зонах: в описании достаточно 3 строк: что
  изменилось, как проверено, какие ограничения.

## Обязательные требования к изменениям

1. Тесты: новое поведение — новый тест. `pytest` должен проходить целиком.
2. Данные: `data/` и `.env` не коммитим, в репозитории только синтетика из `demo/`.
3. Секреты (токены GitHub, service_token команды) в репозиторий не попадают.
4. Обратная совместимость API: существующие методы и поля не переименовываем без
   причины; новое — добавляем, старое — помечаем в README.
5. README и `docs/` поддерживаем в актуальном состоянии: жюри читает их первыми.

## Проверка перед сдачей

```powershell
cd promise-service
python -m pytest -q

# сервер и сквозной сценарий
python -m uvicorn app.main:app --port 8000
python demo\run_demo.py
```

Демо можно запускать повторно: дубли звонков отсекаются, уже созданный тип
обещания не приводит к ошибке.
